# 社工覆核與匯出改善計畫

使用者已於 2026-10-21 回覆「修改」，採納前一則評估的四項優先工作。基準提交：`0d85be6406086450b7fdccbf25e6e5e158ba3b05`。工作分支：`codex/review-workflow-improvements`。

## 共通要求

- 個案、人物、覆核狀態與復原紀錄只在本頁記憶體；不新增上傳、追蹤、外部字型或個案持久化。
- 人物與別名須人工確認；不同案件隔離。批次套用只限目前文件，不能因同名跨文件自動合併。
- 任何影響處理結果的修改，均撤銷相關項目的已核對狀態及全文覆核。復原不能恢復過期的匯出許可。
- 保留既有原格式結構安全檢查、輸出後原值殘留檢查、中性檔名及加密對照分離；取消後不能下載。
- 界面使用繁體中文。保留製作署名。測試、文件及截圖只用合成資料。
- 本批不實作 PWA、相對日期、地址層級、外部 AI 呼叫或自動猜測人物關係。
- 完成後開 PR，檢查通過後合併並部署原本 GitHub Pages 網址。使用者本次修改授權沿用目前線上產品的發布流程。

## Task 1：在地規則與批次人物輸入

負責檔案：`engine.ts`（或新的小型在地規則模組）、`views-input.ts`、新增人物清單解析模組，以及相關測試。

1. 增加有上下文的車牌、LINE ID、統編辨識：以明確標籤（車牌／車號、LINE ID／LINE帳號、統一編號／統編）為優先，不把普通英數代碼、日期或八位數字一律視為個資。LINE 格式支援一般英數及點、底線、連字號；拒絕空值／過長值；保留輸入大小寫。車牌支援常見英數連字號格式，仍明示非完整辨識保證。使用既有統編檢核；有標籤且疑似錯字的號碼可列候選覆核，不宣稱有效證件。
2. 人物頁增加「批次加入人物」：一行一人，可輸入姓名，或 `姓名<TAB>角色<TAB>別名1、別名2`。顯示範例及本次記憶體限定的說明。解析後先預覽新增數、重複／錯誤行，再明確按鈕加入；全部新人物均未確認，不自動猜測角色或合併別名。
3. 同一案件內完全同名者略過並提示，其他案件同名不受影響。錯誤行不得悄悄忽略；使用者修正後再加入。限制最多 100 行、每個姓名／別名 120 字元、最多 20 個別名；角色必須來自既有清單或留空為「待確認」。不更動既有已確認人物的別名。
4. 依測試驅動方式驗證有標籤的正例、普通代碼／八位數的反例、別名未自動確認、跨案隔離、重複行及無效行不部分匯入。保留既有界面測試。

## Task 2：覆核效率、復原與可讀性

負責檔案：`views-review.ts`、新的 `review-actions.ts`（純狀態操作）、`session.ts` 必要的記憶體狀態、`app.css` 及覆核測試。可小幅調整 `views-input.ts` 的首頁信任說明。

1. 顯示目前文件「剩餘 N 項待核對」，提供全部／未核對篩選、上一項／下一項／下一個未核對項。定位時移動焦點並提示位置；大型清單分批顯示，保留全文件總數，不得因未呈現的項目而放行匯出。
2. 既有項目可改分類。非人物標記的遮罩標籤隨分類更新；人物標記不可因此破壞一致的角色代號。名稱驗證沿用引擎限制。
3. 同詞批次套用採明確預覽：目前文件、原文完全相同、相同人物識別（含無 personId），且相同原分類的項目才可納入。顯示影響數及排除歧義數，再按確認按鈕套用。只套用處理方式／分類／概括文字，不能把 personId 或人物角色錯配；變更項目均變成未核對。不要自動擴及其他案件或文件。
4. 新增記憶體內最近操作復原，至少涵蓋單項處理、分類、批次套用與手動新增；最多 20 步。復原撤銷全文覆核，影響項目需重新核對。重新分析、案件／用途／人物規則改變及清除後，不得保留可恢復過期判斷的歷史。
5. 鍵盤操作限定覆核工具列／項目容器有焦點時：提供明確列出的上一項、下一項、核對與復原快捷鍵；不使用 Delete 放行原文，不攔截輸入框、選單、textarea 的正常編輯及輸入法組字。焦點回復應能持續操作，不能每次重畫丟掉焦點。
6. 原文標記保留文字內容與範圍選取能力，以非文字插入方式提供類別及核對狀態的可及名稱；清單提供「待核對／已核對」文字。不能因加標籤破壞原文 offset 或手動反白。
7. 覆核本文 18px；重要欄位、核對文字、錯誤／格式限制至少 16px。補 PingFang TC，保留系統字型與本站資源。一般文字對比至少 4.5:1、焦點／必要控制邊界至少 3:1；不能僅以 CSS 宣稱全面 WCAG 合格。手機與 200% 縮放不遮住必要操作。
8. 首頁可見「個案檔案不上傳；開啟網站需下載程式資源」。不宣稱已完成實際斷網驗收。
9. 行為測試涵蓋批次作用範圍、未確認阻擋、復原失效、鍵盤輸入安全、篩選與分批不漏算、保留原文手動選取 offset。視覺調整以瀏覽器驗收，避免只檢查 CSS 字串的測試。

## Task 3：匯出前第二輪疑似項目檢查與摘要

負責檔案：新的 `output-scan.ts`、`export.ts`、`views-output.ts`、必要的 `session.ts` 型別，以及測試。

1. 保留原值殘留硬性阻擋；不可讓任何新勾選繞過它。保留 DOCX/XLSX/PDF 真正產生後的現有檢查。
2. 在處理後的文字上再次執行現有在地規則與人物候選辨識；明確說明這是同一套規則的再檢查，不是完整匿名保證。不要只掃原文，也不要宣稱未知姓名都能找到。
3. 精確映射人工已核對且選「保留原文」的輸出範圍，列為「已確認保留」，不重複無限攔截。不能僅用字串白名單，否則另一位置相同文字會被錯誤放行。掃描結果要能辨別出現在新增概括文字中的姓名、電話等疑似內容。
4. 匯出頁顯示逐文件檢查摘要：全文與項目覆核、格式限制、已確認保留數、新增疑似項目數、已知原值檢查的實際階段。未產生檔案前不得聲稱封裝檢查已通過。
5. 新增疑似項目需列出原由、可回覆核修改，並允許使用者明確確認其適合用途後繼續；此確認只限這份文件目前完全相同的輸出及判斷狀態。任何修改／重分析／清除後失效。使用精確狀態或密碼學摘要比對，不能以易碰撞短雜湊當成授權。
6. 單檔下載、分享包與複製都必須遵守相同檢查；不可只在按鈕禁用、底層函式仍放行。取消或切換／修改後不得利用舊檢查結果下載。原文或疑似項目不寫入分享包摘要、日誌或儲存空間。
7. 警語只保留必要資訊，不增加重複彈窗。無新疑似項目時不增加多餘確認步驟。
8. 測試包括概括文字新插入識別資訊、精確保留範圍、另一位置同值仍提示、核准後修改失效、原值殘留不可略過、各種輸出路徑一致及取消。

3. 既有虛構 Word／PDF 上傳、確認人物、覆核、原格式下載並重新讀取；執行 `verification.html`。
4. 檢查一般桌面、手機窄螢幕與放大版面；量測主要文字／狀態／焦點對比。使用合成長文件驗證清單分批和總數門檻。
5. 更新 README／驗收紀錄／進度，開 PR、確認 CI、合併部署、核對正式站與建置一致，保存線上截圖及驗收結果。
6. 不把測試通過描述為實務社工試用已完成；離線 ZIP 只有重建並驗證才可標示包含本次功能。
